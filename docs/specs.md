# 기능 명세

무엇을 만들기로 했는지를 화면+API 단위로 정리한 문서. "왜 이렇게 정했는지"는 `docs/decisions.md` 참고.

## 화면 디자인 참고

`docs/design-reference/`에 Figma Make로 받은 8개 화면 × 라이트/다크 스크린샷 16장이 있음. 파일명: `01-login`, `02-signup`, `03-home`, `04-transactions`, `05-budget`, `06-dashboard`, `07-goals`, `08-profile` (다크는 `dark-` 접두사).

- 이 스크린샷은 **확정된 최종 디자인이 아니라 지금 시점에 참고할 수 있는 유일한 자료**임. 실제 구현하면서 컨셉 컬러나 레이아웃 구성이 달라질 수 있음 — 바뀌어도 괜찮은 참고자료로 취급.
- 디자인 방향(참고 시점): 오프화이트 배경(`#F7F5F0`)+블루 accent, 수입=teal 계열, 지출=중립 회갈색, 예산초과 같은 진짜 경고 상황에만 별도 색 사용. 좌측 다크 사이드바(6개 메뉴: 홈/거래내역/예산/통계/목표자산/마이페이지) + 우측 콘텐츠 레이아웃.
- 실제 구현 시: React 컴포넌트를 짤 때 해당 화면 스크린샷을 열어서 레이아웃·간격·색을 보고 JS(+CSS 또는 Tailwind)로 새로 작성. 코드 복사가 아니라 "이 스크린샷처럼 보이게 만든다"는 시각적 기준으로 사용.
- 8개 화면을 기능 명세와 전체 대조해서 기능 누락이 없음을 확인함(2026-08-07) — 상세 대조 기록은 `docs/troubleshooting.md` 참고.

## ①단계 — 로그인/회원가입

로그인 식별자는 **이메일을 아이디로 사용**(별도 username 없음) — 가계부는 개인용 서비스라 아이디의 "별명" 성격이 크게 필요 없고, 구조도 단순해짐.

- **회원가입 화면**: 이메일(필수, 형식 검증, 중복 불가) / 비밀번호(필수, 영문+숫자 조합 8자 이상) / 비밀번호 확인(일치 검증) / 닉네임(필수). `POST /api/auth/register`. 성공 시 로그인 페이지 이동, 실패 시 필드별 에러 메시지.
- **로그인 화면**: 이메일 / 비밀번호. `POST /api/auth/login`. 성공 시 토큰 저장 후 홈으로 이동, 실패 시 에러 메시지(불일치/탈퇴 계정 등).
- **마이페이지 화면**: 이메일·닉네임·가입일 표시. 닉네임 수정(`PUT /api/users/me`), 비밀번호 변경(`PUT /api/users/me/password`, 현재 비밀번호 확인 필요), 회원탈퇴(`DELETE /api/users/me`, 비밀번호 확인 필요, 되돌릴 수 없음을 안내하는 확인 모달 필요). 탈퇴는 즉시 하드 삭제가 아니라 소프트 삭제 후 30일 유예 기간을 두고, `UserCleanupScheduler`가 매일 30일 경과 계정을 완전 삭제.
- **공통 헤더/네비게이션**: 로그인 여부에 따라 "로그인/회원가입" ↔ "마이페이지/로그아웃" 표시 전환. 로그아웃 시 토큰 삭제 + 로그인 페이지 이동.
- **로그인 후 진입 화면 (②단계 전까지)**: 실제 대시보드 대신 "환영합니다" 수준의 **임시 플레이스홀더 화면**만 둠. ①단계의 완료 기준은 화면의 완성도가 아니라 "인증(로그인/회원가입/토큰 관리/탈퇴)이 정상 동작하는가". 이 플레이스홀더 자리는 ②단계에서 실제 대시보드로 교체됨.

## ②단계 — 거래/예산/카테고리/대시보드

- **거래(수입/지출) 관리**: 단건 기록만 (반복거래·다중통화는 최초 범위에서 제외).
  - 거래 목록 화면: 날짜·카테고리·유형·금액·메모 표시, 최신순 정렬, 월 단위 필터(`GET /api/transactions?month=2026-07`)
  - 거래 등록/수정: 유형(수입/지출)·카테고리(고정 목록에서 선택)·금액·날짜·메모(선택). `POST /api/transactions`, `PUT /api/transactions/{id}`, `DELETE /api/transactions/{id}`
- **카테고리** (고정 목록, CRUD 없음 — `GET /api/categories`로 조회만):
  - 지출(10개): 식비, 교통비, 주거비, 통신비, 문화/여가, 의료/건강, 쇼핑, 교육, 경조사/선물, 기타
  - 수입(5개): 급여, 용돈, 부수입, 금융소득, 기타
- **예산 설정**: 카테고리별 월 예산 입력, 예산 대비 실제 지출 비교(진행률 바). `POST /api/budgets`, `GET /api/budgets?month=2026-07`, `PUT /api/budgets/{id}`
- **대시보드**: 백엔드가 집계해서 내려줌.
  - `GET /api/dashboard/summary?month=2026-07` → 이번 달 총수입/총지출/순액, 전월 대비 증감률 포함
  - `GET /api/dashboard/category-breakdown?month=2026-07` → 카테고리별 지출 합계 (파이차트용), 가장 많이 지출한 카테고리 포함
  - `GET /api/dashboard/monthly-trend?months=6` → 최근 6개월 월별 지출 (막대/라인차트용)
  - 검토했으나 보류한 항목(사용자별 평균 지출, 3개월 소비 패턴)은 `docs/decisions.md` 참고

## ②-2단계 — 목표자산(Goal)

"1억 모으기", "결혼자금 모으기"처럼 목표를 세우고 진행률을 추적하는 기능. ②단계(거래 기록+통계)가 끝나고 CRUD+통계 감각이 익은 뒤 확장 단계로 진행.

- **목표 등록/목록**: 여러 목표를 동시에 등록 가능(목표명, 목표금액, 마감일). 상태는 활성(진행 중) 1개 + 대기 중 여러 개, 순서 지정 가능(하나 끝나면 다음 목표가 활성화). `POST /api/goals`, `GET /api/goals`, `PUT /api/goals/{id}`, `DELETE /api/goals/{id}`
- **활성 목표 자동 반영**: 매달 마감 시(또는 배치) 그 달의 순저축액(수입-지출, ②단계 대시보드 summary와 동일 계산)을 활성 목표 1개의 현재금액에만 자동으로 누적. 여러 목표에 동시에 자동 배분하는 로직은 만들지 않음(활성 목표가 하나뿐이라 배분 자체가 불필요). 정확히 언제를 "월 마감"으로 볼지, 순저축액이 마이너스일 때 어떻게 처리할지 등은 미확정 — 구현하면서 조정.
- **메인화면 노출**: 로그인 후 진입 화면에 활성 목표의 진행률을 요약 표시 (예: "🏠 1억 모으기 — 42% (4,200만원 / 1억)").

## ③단계 — 소셜로그인(구글)

지원 제공자는 **구글 하나로 확정**. Spring Security OAuth2 표준 흐름 기준으로 새로 학습해서 구현.

- **흐름**: 사용자가 "구글로 로그인" 클릭 → 구글 인증 → 구글이 이메일 등 신원 정보를 서버에 전달 → 서버가 그 이메일로 기존 User 존재 여부 확인 → 있으면 로그인 처리, 없으면 자동 회원가입(비밀번호 없이 `provider="GOOGLE"` 기록) → 이후 JWT 발급/필터/SecurityContext 흐름은 일반 로그인과 완전히 동일.
- **계정 병합 정책 — 자동 연결로 확정**: 같은 이메일이면 가입 경로(일반/구글)와 무관하게 항상 같은 User 계정으로 귀결시킴.
  - 일반 가입 후 같은 이메일로 구글 로그인 시도 → 자동으로 기존 계정에 로그인 처리(새 계정 안 만듦), 기존 데이터 그대로 보임.
  - 구글로 먼저 가입한 계정에 같은 이메일로 일반 회원가입(비밀번호 설정) 시도 → **안내만 하고 막음**("이미 가입된 이메일입니다, 구글로 로그인해주세요"). 비밀번호를 기존 구글 계정에 추가 등록하는 기능은 만들지 않음. 즉 구글로 가입한 계정은 이후로도 구글 로그인만 가능.
